# Agent guide

`pi-context-decisions` is a Pi extension with four decision backends, one internal `bool`/`choice`/`score` API, and **score-only, additive** skill-advertisement picking. Load it early. **Opt-in (default off) tool/MCP filtering is implemented as relevance gating through public Pi APIs; it is not a sandbox or permission boundary.**

## Layout and status

- `src/extension.ts`: Pi package entry (`<agentDir>/pi-context-decisions/settings.json`); `src/extension/`: lifecycle, `/decisions` user settings command, host contracts. Register only `decisions`; no compatibility alias.
- `src/settings-schema.ts`: `pi-extension-settings-tui` (`>=0.5.0`) declarative schema (`version: 5`, 4 tabs: `Skills`, `Tools`, `Decision`, `Lab`), `FlatContextDecisionsSettings`, inline v4/pre-0.3 → v5 migration (`migrateLegacySettings`), legacy global allowlist extraction (`extractLegacyGlobalAllowlists`), and bidirectional `flatToContextSettings` / `contextSettingsToFlat` adapters.
- `src/settings.ts`: `createDecisionsSettingsStore`, strict fail-closed validation, atomic `0o600` override-only persistence via `pi-extension-settings-tui` (`loadSettings` with `persistMigration` writing `allowlists.json` before rewriting `settings.json`, `saveSettings`, `parseSettings`, `updateSetting`).
- `src/settings-error.ts`: `SettingsError` (`code = "config"`).
- `src/project-allowlist.ts`: hardened read-modify-write for both `<cwd>/.pi/pi-context-decisions.json` and global `<agentDir>/pi-context-decisions/allowlists.json` (`{ alwaysAllowed, alwaysAllowedTools, alwaysAllowedMcpServers }`); `src/apps/allowlist.ts`: pure scope policy.
- `src/extension/skill-state.ts`: advertised names derived from committed Pi system sections; `src/apps/skill-additions.ts`: pure additive scoring (`scoreAdditions`, `RelevanceScoreCache`). `src/extension/runtime.ts` wires them into `before_agent_start`.
- Tool/MCP filtering (separate feature, `settings.tools`, default off): pure `src/apps/tool-inventory.ts` (provenance classification, MCP namespace and extension groups, candidates), `tool-policy.ts` (availability, promotion, reconcile), `tool-additions.ts` (`IncrementalScoreCache`, `scoreToolAdditions`; `relevance.ts` has a `subject` option for tool/MCP request shapes); `src/extension/tool-ledger.ts` (branch ledger `context-decisions-tools` + names-only notice), `tool-filter.ts` (boundaries, `setActiveTools` reconciliation, `tool_call` gate), `queued-task.ts`. Both global `allowlists.json` and project `.pi/pi-context-decisions.json` hold `alwaysAllowed`/`alwaysAllowedTools`/`alwaysAllowedMcpServers`.
- `src/extension/decisions-history.ts` & `src/extension/history-dialog.ts`: read-only `/decisions history` derived from committed active-branch records and Pi system skills sections. New scored skill picks retain names, numeric score and threshold in non-context `context-decisions-skill-scores` entries linked to committed native sections; older native-only advertisements and unscored selections have no score. Tool grants retain numeric picks and allowlist marks in the existing tool ledger. `history-dialog.ts` hosts the standalone read-only terminal overlay (`history` -> `history-batch` route stack, `createHistoryDialogManager`); RPC/print use a bounded report.
- `src/extension/commands.ts`: registers `/decisions` using `pi-extension-settings-tui` `openSettingsDialog` (4-tab TUI with mouse support, refreshable Markdown `Status` viewer, async `Decision model` picker, `field.model` housekeeping model picker, row eligibility checks, dynamic `Tools` / `MCP/exts` labels, RPC/headless fallbacks) plus `status`, `history`, `test`, `tools list`, `mcp list`, and `pin`/`unpin`; `settings-model.ts`: pure terminal text sanitization, error formatting, `dialogHeightBudget`, and `layoutMenu` helpers (no Pi/TUI imports). `src/extension/allowlist-picker.ts`: A-Z/fuzzy and explicit relevance-ranked scoped editor (and nested tool/MCP/extension tree editor), mounted as ejected `field.external` sub-routes inside `openSettingsDialog`.
- `src/index.ts`: portable application/core exports.
- `src/decision/`: canonical primitives, validation, client, typed errors.
- `src/core/`: Pi classifier and direct TypeSafe/OpenAI/OpenRouter transports/codecs/auth.
- `src/host/pi-credentials.ts`: opt-in standalone public SDK credential adapter, exported as `./pi-credentials`; active extensions keep using `ctx.modelRegistry`.
- `src/catalog/`: **static checked-in OpenRouter catalog**: retained top-ten entries plus explicitly requested variants from the same leaderboard, with pure picker merge. Snapshot 2026-11-21, token window November 14–20. Future updates require code changes, never runtime discovery.
- `src/apps/`: metadata-only relevance and skill policy; public `pickSkills` composes existing ranking/filtering for all four backends. Explicit picks default to no inventory minimum; automatic hook defaults to eight.
- `test/`: offline fixtures and mocked real Pi registration/lifecycle/commands. `test/helpers/settings-ui.ts` changes settings the way users now can (RPC menus: `setSetting`, `setModel`; the real terminal editors: `saveAllowlist`) because no setter subcommands exist. `test/helpers/pi-sim.ts` is an offline stand-in for Pi's branch/compaction/context-edit projection and before_agent_start/turn_end commit order: a contract fake, not a Pi test. `test/extension-real-pi-session.test.ts` drives the REAL `AgentSession` (faux provider, in-memory session, injected decision client; offline) to check Pi's actual commit order, branch contents, context conversion, steering, tool rounds and compaction.
- `.agents/skills/`: project-local skills; `.agents/plans/`: pending implementation handoffs (none pending now); `.agents/research/`: archived research and live-validation evidence.
- `../pi-skill-picker-jev`: pattern reference only; do not copy wholesale or add as a dependency.

Archived research proposed dynamic discovery and fail-open defaults. Latest user requirements override it: **static ranked snapshot with explicit additions/exclusions, and default fail closed**, explicit fail-open optional. Completed and superseded plans have been pruned; keep pending work in `.agents/plans/`. Preserve historical evidence in `.agents/research/`; add a uniquely named follow-up when needed.

## Working rules

- Read installed Pi docs fully and relevant linked declarations before changing host APIs. Current implementation targets `@earendil-works/*` Pi `>=1.5.0` (with `pi-extension-settings-tui >=0.5.0`), not legacy namespaces.
- Read callers/tests before editing; name the files, behavior, and falsifying check. Keep changes scoped and preserve concurrent edits.
- Researchers/architects hand off through `.agents/plans/`. Mark proposed work clearly; do not describe plans as implemented.
- Keep dependency direction: apps/core → decision; extension → layers. Pure app/decision/catalog modules must not acquire Pi runtime dependencies.
- Binary aliases belong only at provider codec boundaries; internal applications use `bool`. Do not fabricate optional metadata or cost.
- Credentials for all three direct providers come from public request-time `getProviderAuth` first, then env (`OPENROUTER_API_KEY`, `OPENAI_API_KEY`, `TYPESAFE_API_KEY`). Exact `openai` API key only, never `openai-codex`/current-chat substitution. Reject OpenAI source `OAuth` even when cached snapshots are empty; do not blanket-reject OpenRouter OAuth. Standalone SDK adapter respects Pi defaults (`~/.pi/agent`, overridden by `PI_CODING_AGENT_DIR`) and disables startup model-network refresh. Delegate references/commands to Pi; never read auth files directly, log keys, or persist secrets/settings tokens.
- Skill decisions send bounded latest user text and candidate names/descriptions. Tool/MCP decisions additionally send only their existing bounded candidate metadata (names, descriptions, labels and group members as applicable). For prompt cadence, the user explicitly approved `state.previousReply` containing only bounded visible text of the immediately preceding run's final assistant message. For opt-in tool-round cadence, the user explicitly approved `state.activity`: bounded recent assistant-authored text and direct tool-call names/arguments since the latest user prompt; these may include sensitive project data and go to the selected provider. For opt-in [lab] Past Turn Summaries, the user explicitly approved bounded model-written summaries of earlier visible prompts and final assistant replies as `state.history` to skill/tool/MCP decisions. The selected housekeeping provider receives bounded visible prompt/reply text; summaries are not chat context. Never forward tool-result bodies, thinking, images, skill bodies/locations, earlier transcript, parameter schemas, annotations, namespace instructions, provenance paths or server configs. Queued user prompts reset activity. Diagnostics contain only safe codes/counts/usage. Canonical skill locations appear only in the chat-model system skills section.
- **Fail closed** on active decision/configuration errors: a failed round adds nothing and never removes. Adding every remaining skill requires explicit `failMode: "open"` (never for config errors or aborts). Disabled/unconfigured/below-minimum intentionally makes no calls and keeps every skill advertised; Pi records the native system skills section, so later enabling cannot drop a skill the model saw.
- **Skill picking is score-only; the `choice` decision primitive stays for the library/smoke test only.** Settings have one framework-wide normalized `decisionThreshold` (`settings.decision.threshold`) in [0, 1] (default 0.375), inclusive: a skill qualifies when its 0–2 score is at least `2 × threshold` (exact in IEEE-754). `mode`, `minLabel`, `relatedThreshold` and `directThreshold` exist only as load-time migration inputs (`threshold = (minLabel === "directly_relevant" ? directThreshold : relatedThreshold) / 2`; `mode: "choice"` migrates with one warning; invalid legacy values stay errors and never rewrite the file; valid legacy files migrate inline on first run when `persistMigration: true`) and as rejected options to the app API. `RelevanceItem` has no label. `chunkSize` (1–50) is the shard size, defaulting to 50 with `concurrency: 0` (all shards parallel); reduce it for a lower declared provider/client `maxQuestions`; evaluate every candidate, not just the first shard. `maxSkills` is the cap on NEWLY added skills per round, ranked globally across shards (never per shard, no session total); pins/manual-only policy and stable references survive.
- **Additive native advertisement.** Never remove an advertised skill. By default exclude advertised names before sharding; the opt-in constant-matrix lab scores all invocable skills in stable name order, excluding advertised names only when choosing additions and applying the cap. In `before_agent_start`, set `systemPromptOptions.skills` to the cumulative selected inventory. Derive advertised names from committed system skills sections on the active branch; Pi owns rendering, transcript updates and compaction. Skills are picked on submitted prompts only, not at `turn_end` or queued-user boundaries. Preserve pins, cancellation and fail-closed behavior; do not claim advertisement without an active `read` or `bash` reader. Never add custom skill messages or base records, use `context`/`context_with_system`, edit provider payloads or retain Pi's private run options. Pi's native mid-conversation system support is provider/model dependent: unsupported routes can fold updates into the leading prompt and invalidate cache; cache hits are never guaranteed.
- `/decisions` uses `pi-extension-settings-tui` (`openSettingsDialog`, `saveMode: "immediate"`, override-only flat v5 persistence in `<agentDir>/pi-context-decisions/settings.json`, fullscreen mouse + keyboard navigation) with four peer tabs: **Skills** (`skillFilteringEnabled`, `skillMaxAdded`, `skillMinCandidates`, ejected `globalSkillAllowlist` / `projectSkillAllowlist`, refreshable Markdown `statusView`, hidden `pinnedSkills` managed only via `pin`/`unpin`), **Tools** (`toolFilteringEnabled`, `toolMode`, `toolCadence`, dynamic-label `toolMaxAdded` / `toolMinCandidates` switching between `Tools · …` and `MCP/exts · …`, `allowSubagentInheritedTools` with `eligible` gray-out when `pi-subagent-manager` is absent, and four ejected allowlist editors `globalToolAllowlist` / `projectToolAllowlist` / `globalMcpAllowlist` / `projectMcpAllowlist`), **Decision** (async searchable/refreshable `backend` `Decision model` picker, `decisionThreshold`, picker-only `decisionFailMode` with `allowInlineStep: false` and explicit `open` warning, `decisionChunkSize`, `decisionConcurrency`, `decisionTimeoutMs`, `decisionMaxPromptChars`, `decisionMaxDescriptionChars`, `iconStyle`), and **Lab** (`constantMatrix`, `historyModel` via `field.model` `{ model, thinkingLevel } | null`, `historyEnabled` with `eligible` gray-out until a usable authenticated model is selected; clearing `historyModel` disables `historyEnabled`). No master switch. Shared `decision*` fields apply across skill picking, tool/group picking, lazy tool decisions, and explicit allowlist ranking (ranking sorts only); skill/tool caps and minimum inventory gates stay distinct policy (skills 12/8 vs tools 8/0). Legacy v4/pre-0.3 nested `settings.json` files migrate inline on first run (`loadSettings(path, { persistMigration: true })`): legacy global allowlists (`globalAllowlist`, `tools.alwaysAllowedTools`, `tools.alwaysAllowedMcpServers`) are extracted and persisted to `<agentDir>/pi-context-decisions/allowlists.json` **first** (when absent) before `settings.json` is rewritten into flat v5 overrides; explicit `decision.*` wins per field, conflicting legacy policies use higher threshold / shorter description / closed if either was closed, old `enabled: false` disables both switches, and even shadowed legacy values are validated strictly so corrupt files fail closed. The tool editor stays NESTED: locked built-ins first, then collapsible MCP-server and extension groups with `[ ]`/`[-]`/`[x]` headers, then ungrouped tools; header Space pins the group key, child saves its tool name, one save writes both lists, unloaded names/keys remain stable rows even on deselect; MCP editor is the same group list, flat. Allowlist editors mount as ejected `field.external` sub-routes inside the single `openSettingsDialog` overlay; never stack nested `ctx.ui.select`/`input`/`custom` overlays inside it. `/decisions history` opens its own standalone `createHistoryDialogManager` overlay (`src/extension/history-dialog.ts`, `history` -> `history-batch`) when invoked directly. RPC uses `pi-extension-settings-tui` select/input menus (`Skills` / `Tools` / `Decision` / `Lab`; allowlist editors remain terminal-only). **The dialog is the only place settings change: do not add `/decisions` setter subcommands** (`status`, read-only `history`, `test`, read-only `tools list`/`mcp list`, and `pin`/`unpin` only). Print/JSON mode prints status; settings there are file edits plus `/reload`. Provider/model availability uses public request-time Pi credential resolution, not chat-model inventory guesses; label missing keys and guide to env vars or `/login <provider>`. Reject unusable selections before persistence; never enable filtering as a side effect of selecting a model.
- Scoped allowlists mean **always included**, not restrict-to-only: for skills/extensions/extension-provenance MCPs, global matches public `sourceInfo.scope` user/temporary/missing, project matches project scope only. **User-approved built-in MCP exception:** read server origins from `<getAgentDir()>/mcp.json` then trusted `<cwd>/.pi/mcp.json` (the exact Pi loader paths/order; honor `PI_CODING_AGENT_DIR`, no ancestor discovery). Use public `ctx.isProjectTrusted()`; missing/unreadable trust means no project read. `src/host/mcp-config-scopes.ts` mirrors Pi validation transiently: full valid project definitions replace as Project; settings-only overrides retain Global; rejected project entries retain a valid global definition (including Pi's transport-independent `"url" in config && config.auth` project-auth rejection); hyphen/underscore namespace clashes are rejected. Files are bounded to 64 KiB/1000 entries, regular-file-only (no file symlinks), read-only. Only canonical names/scopes and safe warning codes may escape; never retain/cache/log/forward/persist commands, args, env, URLs, headers or secrets. No execution, config writes or file watching. Capture names/scopes at `session_start` alongside Pi's own load, even if filtering starts off; reuse the capture for classifications/gates/editors until reload or session replacement. Disk edits must not relabel unchanged live connections. Settings/allowlist saves and `session_tree` retain the capture; only session start/shutdown reset it. Missing optional config files (including absent parent directories) contribute nothing silently; unreadable/unsafe/malformed scopes contribute nothing and warn safely. Unresolved built-in origins keep Global fallback. Apply config scope ONLY to `sourceInfo.source === "builtin"` / `path === "builtin:mcp"` namespaces; other tools retain provenance. Tool/MCP editors retain scope (never relabel items to the edited list). Global lists save separately to `<getAgentDir()>/pi-context-decisions/allowlists.json` (`{ alwaysAllowed, alwaysAllowedTools, alwaysAllowedMcpServers }`); project lists save to `<cwd>/.pi/pi-context-decisions.json`. Resource-only MCP names use known file scope or Global fallback; absent `ext__` extensions grant nothing until observable. A group inherits members' common scope; mixed-origin groups cannot be pinned whole, but individual scoped tools remain selectable and do not promote the opposite origin. Relevance/earlier whole-group ledger grants remain additive. Pins bypass scoring/threshold/cap and survive fail-closed. Persist names only; global and project allowlist files stay bounded, regular-file-only, atomically written; malformed lists warn and become empty, never full inventory.
- `/decisions` settings expose both allowlist editors via ejected `field.external` sub-routes. A-Z search is local; typing/tabs make no calls. Only explicit Ctrl+R/search Enter ranks the query with configured decisions (`rubric: "topic"`, configured shared decision batching/concurrency/deadline/metadata limits); no model/key gives inline setup guidance. Cancel old/closed ranking, reject stale completions, show stale query state. Save only on explicit Ctrl+S; preserve unloaded names. The editors are terminal-only (RPC reports guidance to edit `allowlists.json` / `.pi/pi-context-decisions.json`; print/JSON edit the files and `/reload`); never call custom overlays outside `mode === "tui"`.
- `[lab] Past Turn Summaries` lives on the **Lab** tab: `historyModel` (`field.model` `{ model, thinkingLevel } | null`, default `off`) first, `historyEnabled` (`eligible`-gated on an available authenticated `historyModel`; clearing `historyModel` resets `historyEnabled` to `false`) second. Clamp `thinkingLevel` to model support at request time and omit reasoning for non-reasoning models. Existing enabled settings without a usable model load unchanged and make no housekeeping calls.
- Keep terminal text sanitized and visible-width bounded; propagate focus to Input for IME. Mocked key/render tests are not a visual terminal pass.
- Dialog lifetime and context: dialog work uses a dialog-owned `AbortSignal`, never `ctx.signal` (that is the agent-run signal) and never a spread `{...ctx}`; use `scopedContext`, whose `ui`/`modelRegistry` getters throw once the dialog is closed (Pi invalidates every ctx property after reload). `registerCommands` returns `closeDialogs()`, called FIRST and synchronously in `session_shutdown` (and at `session_start`), aborting active settings dialog work and calling `historyDialogs.closeAll()` because Pi removes a custom overlay on reload without resolving it. Dialogs are NOT in `pending`: settings saves abort in-flight decisions, never the dialog. Custom overlays (`history-dialog.ts`, `allowlist-picker.ts`) must respect `dialogHeightBudget(rows)` / `maxRows` because Pi slices overlay output at `maxHeight`. Dialog errors render inline, not as transcript notifications.
- While the dialog has focus the session keeps streaming underneath, but Esc/Ctrl+C act on the dialog, not the agent. A key that hands typing back while the dialog stays open is deliberately not implemented.
- **Subagent diagnostics:** require explicit stable semver >= **1.1.0** (`MIN_SUBAGENT_MANAGER_DIAGNOSTICS_VERSION`) and `protocol: 1` via synchronous `respond({ version, protocol })`. No legacy no-argument/shape-only fallback. Child-local `pi-subagent-manager:diagnostic:probe` discovers the sink; parent-session `pi-subagent-manager:capabilities:probe` checks integration support. Reject malformed/prerelease/async/duplicate replies. Cache child discovery lazily per session, reset on start/shutdown; refresh parent discovery to tolerate initialization order. When command provenance detects the manager but parent capability is missing/old, warn once per TUI session and expose the requirement/fallback in status and Tools inherited-tools help. Never infer capability from transcript ownership, read manager files or read tool registries. Only safe codes/counts summaries, <=1000 chars, source `pi-context-decisions`. Missing/incompatible hosts or throwing sends fall back to deduplicated stderr; UI, injected sinks and explicit reports bypass routing. Discovery among trusted extensions is not authentication; no acknowledgement, host limits may drop reports.
- **Subagent inherited tools:** `allowSubagentInheritedTools` defaults false on the **Tools** tab (`eligible`-gated with inline setup help when `pi-subagent-manager` is absent, unless already `true`). Enable only with public manager command provenance (tool provenance fallback only while filtering is on; package/local extension source, never names alone; explicit npm identity is authoritative). Persisted `true` remains unchanged (even if `pi-subagent-manager` is absent) but ineffective without manager bridges. In children the observable synthetic `<subagent-inherited-tools>` group `ext__subagent_inherited_tools` is pinned through the ordinary scoped allowlist path, both modes and gate, bypassing scoring/caps/fail-closed. Does not create bridges, override manager policy or sandbox tools.
- **Tool/MCP filtering rules.** Opt-in, `tools.enabled` default false, independent of `relevance.enabled`; off means no `getAllTools`/`setActiveTools` calls, no entries, no extra status writes, every call passes. Two modes: `tools` (each external tool) and `mcp` (group mode: whole groups, where a group is an MCP namespace OR an extension, handled identically; allowlisting or already having ANY tool of a homogeneous-scope group promotes the whole group; mixed-origin groups keep individual grants scoped). **This supersedes the old rule "other extension tools are never filtered" in `mcp` mode**: only extension tools with no usable provenance (no group) pass there. **Internal = Pi-assigned provenance only** (`sourceInfo.source === "builtin"` with a `builtin:` path and no `mcp__` namespace); the MCP namespace check runs FIRST because built-in MCP provenance belongs to external server tools. Never classify by name, `reachesTools` or core-name lists; SDK/extension/unknown-provenance tools are external. Group MCP tools only by Pi's public `namespace.name` (`mcp__<server>`) and extension tools only by Pi's public `sourceInfo` (`extensionFullName`: package `source` (never `.`/`..`), else the RESOLVED `baseDir`; else the synthetic `<kind:name>` path; else the file/dir name; display label = first 48 chars; key = `ext__<name>` within 64 chars from the FULL name: canonical-up-to-case-and-`-` names as is, any other name `ext__<ascii slug>_<10-hex sha256 of the NFC name>`, empty slug `ext__ext_<hash>`; same-named extensions merge, no usable name = ungrouped); never parse tool names, read extension files or guess packages; the bounded names-only built-in MCP config scope exception is defined above. Group allowlist entries are `[A-Za-z0-9_-]{1,64}` or `mcp__`/`ext__` + such a name (the canonical prefix is IN ADDITION to the 64-char bound, in settings, project file, commands and editors). An `mcp__` allowlist entry is exclusively a canonical MCP namespace key and an `ext__` entry exclusively a canonical (lowercase) extension key, both kept in the existing `alwaysAllowedMcpServers` list (a raw server named `ext__x` is `mcp__ext__x`). Extension labels are derived names, never paths, and are the only provenance-derived text that reaches the decision model. MCP resource tools are internal but gated by their `server` argument (resource-only servers require a pin in their known file scope, or Global when unresolved); this is a documented routing policy, not an exception to "internal always allowed". Availability is additive per branch (ledger entries `context-decisions-tools`; the first active boundary on a fresh branch always writes a marker so a late tool is never mistaken for mid-session enabling; enabling mid-session records existing tools as seen, a documented limitation; disabling restores only tools we withheld). Cadences `initial` (first user prompt only; `considered` is persisted so catch-up/reload never re-picks; custom-message runs never supply the task; a failed pick retries), `prompt`, `tool-round`. Only use `pi.setActiveTools` (restore only what we withheld); never edit `selectedTools`, never use `context_with_system`, never prune `sections.mcp_servers`. Calls to unavailable external tools are blocked in `tool_call` (covers codemode/nested); an unscored candidate gets one single-flight lazy decision. Fail closed on config/decision errors; settings errors keep enforcing an existing ledger. Gate policy when the registry cannot be read: use the last classified snapshot (internal pass, known external per ledger/allowlists, unknown blocked; no snapshot blocks all); an unreadable branch is never mid-session evidence (gate only, no writes); stale generations (settings/allowlist save, disable, mode change, branch change) mutate nothing, while a merely cancelled run reconciles from committed state only. Unscoped resource listing is always blocked while filtering is on; resource-only allowlist keys are recorded canonically (`canonicalServerKey`: a `mcp__` prefix is exclusively a namespace key). Unconfigured/below-minimum applies at every boundary and the gate; disabling restores at `turn_end` too. Ledger records are chunked (1000 names per list), never truncated. The notice speaks only about indirect candidates (groups are named by canonical key: `MCP servers: mcp__x`, `extensions: ext__y`). Say plainly in docs/status that it is not a sandbox and discovery (`searchTools`, `tool_search`, `mcp_servers` section) and server connections are unaffected. Skill and tool decision passes run concurrently (the tool `before_agent_start` handler is registered first and starts the skill pass). Tests: `test/extension-tool-filter.test.ts` (sim host), `test/extension-tool-commands.test.ts`, `test/extension-real-pi-tools.test.ts` (REAL `AgentSession`).
- Later extensions may overwrite the selected skills array; Pi/provider compaction and transcript behavior remain outside this extension's control. Never claim tool/MCP filtering is access control.
- Keep native OpenRouter entries constrained to the same static retained list; do not destructively override Pi's provider. Missing native registrations stay errors, not automatic direct-backend fallback.

## Verification and publishing

```bash
npm ci --ignore-scripts
npm test
npm run typecheck
npm pack --dry-run --ignore-scripts
```

Every behavior change needs focused tests and the full offline suite. `test/extension-settings-overlay-render.test.ts` drives Pi's real `TuiMainScreen` into `@xterm/headless` (dev dependency, pinned to the version pi-tui tests with): a renderer test, not a visual terminal pass. An optional manual pass is possible in tmux with an isolated `PI_CODING_AGENT_DIR=$(mktemp -d)`, `--offline --no-session -ne -e ./src/extension.ts` and a `!` bash loop for background output; choose "Do not trust (this session only)" at the trust prompt and delete the temp dir afterwards. Local dev dependencies and lockfile make typecheck reproducible; no sibling tooling is required. Default checks must not make inference calls. Report commands actually run, failure modes, and unverified paths. A mocked UI is not a visual terminal check.

Live smoke validation on 2026-10-12 retained eight OpenRouter models after two confirmed guardrail restrictions; do not replenish the static list automatically. Direct Luna also passed all three primitives using Pi's stored `openai` API key with the env key absent. `scripts/live-smoke.ts` requires explicit `PI_CONTEXT_DECISIONS_LIVE=1` and may incur charges; explicit `gpt-6-luna`/`openai`/`luna` selects only Luna, while the no-argument default excludes it. Smoke credentials are SDK Pi-first/env-second. Default checks remain offline.

Releases: tag-driven via `.github/workflows/release.yml` (npm trusted publishing, no `NPM_TOKEN`); follow `.agents/skills/release/SKILL.md`. Never `npm publish`, tag, or push a tag without explicit user authorization for that release. `0.1.0` is published manually once by the user; keep `package.json` and `package-lock.json` versions in sync.

Do not install, commit, push, or touch network unless authorized. The designated sole Git publisher handles tested milestones; inspect staged content for secrets, never force-push, and leave unrelated work untouched.
